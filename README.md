# Multi-Container Application

A containerized task-management API built with Node.js, Express, MongoDB, and Docker Compose. The repository also includes Terraform configuration for provisioning a cloud virtual machine and Ansible automation for installing Docker and deploying the application. The current Terraform example targets Oracle Cloud Infrastructure (OCI), but the application itself is not tied to a specific cloud provider.

## About

This project demonstrates how to run a Node.js API and MongoDB as separate services. Docker Compose provides the local multi-container environment, while the included infrastructure and deployment files support deploying the same application to an OCI virtual machine.

The API exposes a RESTful task resource at `/api/tasks`. Each task has a required `title` and a `completed` status that defaults to `false`.

## Features

- Express REST API for task management.
- MongoDB persistence through Mongoose.
- Separate application and database containers.
- MongoDB initialization script that creates a dedicated application user.
- Persistent MongoDB data through a named Docker volume.
- CRUD operations for tasks:
  - List all tasks.
  - Retrieve one task.
  - Create a task.
  - Replace or partially update a task.
  - Delete a task.
- Docker image built from Node.js 22 Alpine.
- Terraform configuration for provisioning a cloud compute instance (currently demonstrated with OCI).
- Ansible roles for server preparation, Docker installation, and container deployment.
- GitHub Actions workflow that builds and publishes the API image, then deploys it with Ansible.

## Requirements

For local Docker Compose usage:

- Docker Engine
- Docker Compose v2 (`docker compose`)
- `curl` or another HTTP client for testing the API

For optional infrastructure provisioning and remote deployment:

- Terraform
- An account and credentials for the cloud provider you choose
- Ansible
- An SSH key with access to the target server
- An Ansible Vault password

The repository includes an OCI Terraform example, but OCI is optional. You can use another Terraform-supported provider by replacing the provider, data sources, resources, and variables in `terraform/`, or skip Terraform entirely and deploy to an existing server.

Node.js 22 and npm are only required when running the API directly on the host. The Docker image already provides Node.js 22.

## Installation & Usage

### 1. Get the project

You can either clone the repository with Git:

```bash
git clone https://github.com/JescAude18/multi-container-application.git
cd multi-container-application
```

Or download it as a ZIP archive:

1. Open the repository on [GitHub](https://github.com/JescAude18/multi-container-application).
2. Select **Code**.
3. Select **Download ZIP**.
4. Extract the archive and open a terminal in the extracted project directory.

### 2. Configure environment variables

Create a `.env` file in the repository root. Docker Compose uses these variables for MongoDB credentials, the database name, and the exposed port:

```dotenv
MONGODB_ROOT_USER=root
MONGODB_ROOT_PASSWORD=change-me
MONGODB_APP_USER=todoapp
MONGODB_APP_PASSWORD=change-me-too
MONGODB_DATABASE=tododb
MONGODB_DOCKER_PORT=27017
NODE_LOCAL_PORT=3000
NODE_DOCKER_PORT=3000
```

Use strong, environment-specific values and never commit `.env` or other credential files.

### 3. Start the services

```bash
docker compose up --build
```

The API is available at `http://localhost:3000` by default. The MongoDB data is stored in the `db` named volume.

To run the services in the background:

```bash
docker compose up --build -d
```

To stop the services:

```bash
docker compose down
```

To stop the services and remove the persisted database volume:

```bash
docker compose down -v
```

The initialization script runs when MongoDB initializes a new data directory. If credentials or initialization variables change, remove the volume and start the services again.

### Run without Docker

To run the API directly on a machine with Node.js and a reachable MongoDB instance:

```bash
npm ci
MONGO_URL="mongodb://localhost:27017/tododb" npm start
```

The server listens on port `3000` unless the `PORT` environment variable is set.

## API Reference

The base URL is `http://localhost:3000`.

| Method | Endpoint | Description |
| --- | --- | --- |
| `GET` | `/` | Check that the API is running |
| `GET` | `/api/tasks` | Return all tasks |
| `GET` | `/api/tasks/:id` | Return one task |
| `POST` | `/api/tasks` | Create a task |
| `PUT` | `/api/tasks/:id` | Replace a task |
| `PATCH` | `/api/tasks/:id` | Update selected task fields |
| `DELETE` | `/api/tasks/:id` | Delete a task |

Task request bodies use JSON:

```json
{
  "title": "Learn Docker Compose",
  "completed": false
}
```

`title` is required. `completed` is optional and defaults to `false`.

## How It Works

1. Docker Compose creates the `mongodb` service from the official MongoDB image.
2. MongoDB receives root credentials and application credentials from `.env`.
3. On first database initialization, `mongodb-init/01-create-app-user.sh` creates a `readWrite` user for the configured application database.
4. Docker builds the `app` service with `dockerfile.api`, installs the locked npm dependencies, and starts `npm start`.
5. The API connects to MongoDB using the internal Compose hostname `mongodb`.
6. The named `db` volume keeps MongoDB data when containers are recreated.

The application waits for its MongoDB connection before starting the HTTP server. If the connection fails, the process exits with an error instead of exposing an unavailable API.

## Deployment

### Provision an OCI virtual machine with Terraform

The files in `terraform/` define an OCI compute instance, network attachment, operating system image, and SSH key metadata.

Create a local `terraform.tfvars` from your own OCI values, then run:

```bash
cd terraform
terraform init
terraform plan
terraform apply
```

Do not commit `terraform.tfvars`, Terraform state, private keys, or API credentials.

### Deploy with Ansible

The Ansible playbook in `ansible/setup.yaml` applies the `base`, `docker`, and `container` roles. It updates the host, installs Docker, copies the MongoDB initialization script and generated Compose file, then starts the services.

After configuring the inventory and decryptable vault variables:

```bash
ansible-playbook \
  -i ansible/inventory.ini \
  ansible/setup.yaml \
  --vault-password-file /path/to/vault-password
```

The container role expects an `api_image` value when deploying a pre-built image:

```bash
ansible-playbook \
  -i ansible/inventory.ini \
  ansible/setup.yaml \
  -e "api_image=docker.io/<docker-user>/<image>:<tag>" \
  --vault-password-file /path/to/vault-password
```

### GitHub Actions

The workflow in `.github/workflows/deploy_api.yaml` runs on pushes to `main` or through manual dispatch. It:

1. Builds the API image with `dockerfile.api`.
2. Pushes an immutable image tag based on the commit SHA to Docker Hub.
3. Installs Ansible on the runner.
4. Connects to the configured host through SSH.
5. Runs the Ansible playbook with the image tag that was just published.

The workflow requires repository variables and secrets for Docker Hub authentication, SSH access, and Ansible Vault decryption.

## Error Handling

The API returns JSON error messages with appropriate HTTP status codes:

- `400 Bad Request` for invalid MongoDB IDs, invalid task data, or an empty partial update.
- `404 Not Found` when a requested task does not exist.
- `500 Internal Server Error` for unexpected database or server failures.

MongoDB connection failures are logged during startup and terminate the process so container orchestration can restart it.
